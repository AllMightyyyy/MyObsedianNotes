# Phase 3: Detailed Design and Schema

## 1. Database Schema
Define the tables and their relationships:

### Tables:
- **Users**
  - `id` (UUID, Primary Key)
  - `username` (String, Unique)
  - `email` (String, Unique)
  - `password_hash` (String)
  - `created_at` (Timestamp)
  - `updated_at` (Timestamp)

- **ClipboardEntries**
  - `id` (UUID, Primary Key)
  - `user_id` (UUID, Foreign Key to Users)
  - `content` (Encrypted Text)
  - `timestamp` (Timestamp)
  - `device_info` (String)
  - `is_deleted` (Boolean)

- **Devices** (Optional for tracking devices)
  - `id` (UUID, Primary Key)
  - `user_id` (UUID, Foreign Key to Users)
  - `device_name` (String)
  - `device_type` (Enum: Desktop, Mobile, etc.)
  - `created_at` (Timestamp)

---

## 2. API Specification
Define base URL and endpoints:

- **Authentication**:
  - `POST /auth/signup`: Register a new user.
  - `POST /auth/login`: Authenticate user and return JWT.
  - `POST /auth/logout`: Invalidate JWT.

- **Clipboard Management**:
  - `POST /clipboard/save`: Save a new clipboard entry.
  - `GET /clipboard/history`: Retrieve clipboard history.
  - `DELETE /clipboard/delete/{id}`: Delete a specific clipboard entry.

- **Real-Time Sync**:
  - WebSocket Endpoint: `ws://<backend>/ws/clipboard` for real-time sync.
